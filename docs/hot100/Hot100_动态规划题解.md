## 一、动态规划预备课

很多小白第一次看动态规划，会觉得它像“凭空写公式”。
其实它更像是：

`先把小问题都算出来，再把这些小答案一点点拼成大答案。`

### 1. 什么时候要怀疑这题是 DP？

如果题目有下面这些味道，就要想到动态规划：

- `最值`：最大、最小、最多、最少
- `方案数`：一共有多少种方法
- `可不可行`：能不能凑出来、能不能走到、能不能拆开
- `当前位置依赖前面`：当前答案要看前面几个位置或前面几个状态
- `重复子问题`：同样的小问题会被反复计算

比如这些话，都是 DP 很常见的信号：

- 走到第 `i` 步，最少要几次
- 到当前位置，有多少种方法
- 前 `i` 个数里，最优答案是多少

### 2. 什么叫 `状态 / 转移 / 初始化`？

动态规划最核心就这 3 句话：

1. `状态`：`dp[i]` 这一格到底记什么
2. `转移`：这一格怎么从前面的格子推出来
3. `初始化`：最小的几个情况，答案先手写成什么

你可以把 `dp` 想成一个小账本：

- `状态`：账本这一格写的内容
- `转移`：这一格抄哪几格旧账，再算出新账
- `初始化`：账本最前面几格没人能帮你推，只能先手填

口诀：

`先想 dp 记什么，再想它从哪来，最后补最小情况`

### 3. 一维 DP 最常见的几种题型

Hot100 里很多动态规划题，最后都能落到一维数组 `dp[i]` 上。

最常见的 4 种理解方式是：

1. `走到这里有多少种方法`
   例子：`爬楼梯`

2. `走到这里的最优值是多少`
   例子：`打家劫舍`、`零钱兑换`

3. `前 i 个位置能不能做到`
   例子：`单词拆分`、`分割等和子集`

4. `以 i 结尾时，当前最好是多少`
   例子：`最长递增子序列`、`乘积最大子数组`

虽然题长得不一样，但脑子里都可以先问一句：

`如果我只看前面这一小段，答案能不能先记下来？`

### 4. 动态规划到底在做什么？

图解：

```text
先解决最小的小问题
   ↓
把小问题答案记进 dp
   ↓
后面的题直接参考前面的 dp
   ↓
一步一步推到最终答案
```

所以动态规划不是“猜公式”，而是：

`把重复算过的小答案存起来，后面直接拿来用。`

## 70. 爬楼梯

### 题目

原题：[70. 爬楼梯](https://leetcode.cn/problems/climbing-stairs/)

假设你正在爬楼梯。需要 n 阶你才能到达楼顶。

每次你可以爬 1 或 2 个台阶。你有多少种不同的方法可以爬到楼顶呢？

示例 1：

输入：n = 2
输出：2
解释：有两种方法可以爬到楼顶。
1. 1 阶 + 1 阶
2. 2 阶

示例 2：

输入：n = 3
输出：3
解释：有三种方法可以爬到楼顶。
1. 1 阶 + 1 阶 + 1 阶
2. 1 阶 + 2 阶
3. 2 阶 + 1 阶

提示：

- 1 <= n <= 45

### 思路

这题非常适合入门动态规划。

题目问的是：

`到第 n 阶一共有多少种走法。`

先想“最后一步”：

- 如果最后一步走 `1` 阶，那前面一定已经站在第 `i-1` 阶
- 如果最后一步走 `2` 阶，那前面一定已经站在第 `i-2` 阶

所以，到第 `i` 阶的方法数，就是这两种来源加起来。

这里把动态规划三件事说完整：

- `状态`：`dp[i]` 表示“走到第 i 阶，一共有多少种方法”
- `转移`：`dp[i] = dp[i - 1] + dp[i - 2]`
- `初始化`：
  - `dp[1] = 1`，因为到第 1 阶只有一种走法
  - `dp[2] = 2`，因为到第 2 阶有两种走法：`1+1`、`2`

### 口诀

`到当前台阶，只看前两阶`

### 图解

```text
假设要求 dp[5]

最后一步如果走 1 阶：
那前面必须先到第 4 阶
贡献 dp[4]

最后一步如果走 2 阶：
那前面必须先到第 3 阶
贡献 dp[3]

所以：
dp[5] = dp[4] + dp[3]
```

### 背景知识

- 这是最经典的“斐波那契型”动态规划
- 所谓“斐波那契型”，意思是：当前答案只依赖前面两个答案
- 这题不需要回头试很多方案，只要从小到大顺着推就行

### Python

```python
class Solution:
    def climbStairs(self, n):
        # 如果只有 1 阶或 2 阶，答案可以直接写出来
        if n <= 2:
            return n

        # dp[i] 表示：走到第 i 阶，一共有多少种方法
        # 因为题目要用到下标 1 到 n，所以开 n + 1 个位置
        dp = [0] * (n + 1)

        # 初始化最小问题
        dp[1] = 1
        dp[2] = 2

        # 从第 3 阶开始，依次把后面的答案推出来
        for i in range(3, n + 1):
            # 到第 i 阶的最后一步，只可能来自 i-1 或 i-2
            dp[i] = dp[i - 1] + dp[i - 2]

        # 最终答案就是到第 n 阶的方法数
        return dp[n]
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 更优版

因为只用到前两个值，所以可以压缩成两个变量。

```python
class Solution:
    def climbStairs(self, n):
        if n <= 2:
            return n

        a = 1
        b = 2

        for _ in range(3, n + 1):
            a, b = b, a + b

        return b
```

## 118. 杨辉三角

### 题目

原题：[118. 杨辉三角](https://leetcode.cn/problems/pascals-triangle/)

给定一个非负整数 numRows，生成「杨辉三角」的前 numRows 行。

在「杨辉三角」中，每个数是它左上方和右上方的数的和。

示例 1:

输入: numRows = 5
输出: [[1],[1,1],[1,2,1],[1,3,3,1],[1,4,6,4,1]]

示例 2:

输入: numRows = 1
输出: [[1]]

提示:

- 1 <= numRows <= 30

### 思路

每一行：

- 开头和结尾都是 1
- 中间每个数 = 上一行左上 + 上一行右上

### 口诀

`两边全是 1，中间看上一行`

### 图解

```text
上一行:   1  3  3  1
下一行: 1  4  6  4  1

中间的 4 = 1 + 3
中间的 6 = 3 + 3
中间的 4 = 3 + 1
```

### 背景知识

- `triangle[-1]` 表示最后一行
- 列表可以一行一行构造

### Python

```python
class Solution:
    def generate(self, numRows):
        triangle = []

        for i in range(numRows):
            row = [1] * (i + 1)  # 先把这一行都设成 1

            # 只处理中间部分
            for j in range(1, i):
                row[j] = triangle[i - 1][j - 1] + triangle[i - 1][j]

            triangle.append(row)

        return triangle
```

### 复杂度

- 时间复杂度：`O(numRows^2)`
- 空间复杂度：`O(numRows^2)`

## 198. 打家劫舍

### 题目

原题：[198. 打家劫舍](https://leetcode.cn/problems/house-robber/)

你是一个专业的小偷，计划偷窃沿街的房屋。每间房内都藏有一定的现金，影响你偷窃的唯一制约因素就是相邻的房屋装有相互连通的防盗系统，如果两间相邻的房屋在同一晚上被小偷闯入，系统会自动报警。

给定一个代表每个房屋存放金额的非负整数数组，计算你 不触动警报装置的情况下 ，一夜之内能够偷窃到的最高金额。

示例 1：

输入：[1,2,3,1]
输出：4
解释：偷窃 1 号房屋 (金额 = 1) ，然后偷窃 3 号房屋 (金额 = 3)。
偷窃到的最高金额 = 1 + 3 = 4 。

示例 2：

输入：[2,7,9,3,1]
输出：12
解释：偷窃 1 号房屋 (金额 = 2), 偷窃 3 号房屋 (金额 = 9)，接着偷窃 5 号房屋 (金额 = 1)。
偷窃到的最高金额 = 2 + 9 + 1 = 12 。

提示：

- 1 <= nums.length <= 100

- 0 <= nums[i] <= 400

### 思路

这题不要一上来就背公式，先把题目翻译成人话：

`走到第 i 个房子时，我能偷到的最多钱是多少？`

对第 `i` 个房子，只有两种选择：

- `不偷它`：那最优结果就是前一个房子的最优结果 `dp[i-1]`
- `偷它`：那前一个房子就不能偷，只能接在 `dp[i-2]` 后面，所以是 `dp[i-2] + nums[i]`

两种方案取更大。

动态规划三件事：

- `状态`：`dp[i]` 表示“考虑到下标 i 为止，最多能偷多少钱”
- `转移`：`dp[i] = max(dp[i-1], dp[i-2] + nums[i])`
- `初始化`：
  - `dp[0] = nums[0]`
  - `dp[1] = max(nums[0], nums[1])`

### 口诀

`偷当前，就别偷前一个；不偷当前，就沿用前一个`

### 图解

以 `nums = [2,7,9,3,1]` 为例：

```text
到下标 2，也就是房子 9 时：

方案 1：不偷 9
那就保持前面最好的结果 dp[1]

方案 2：偷 9
那前一个房子 7 不能偷，只能接 dp[0] + 9

两者取最大
```

### 背景知识

- 这类题本质上是在每一步做“选 or 不选”的决策
- `max(x, y)` 的意思是“两种方案里选收益更大的”
- 这题不是贪心，因为不能只看当前房子值大不大，必须带着前面的最优结果一起考虑

### Python

```python
class Solution:
    def rob(self, nums):
        # 只有一个房子时，直接偷它
        if len(nums) == 1:
            return nums[0]

        # dp[i] 表示：考虑到下标 i 为止，最多能偷多少钱
        dp = [0] * len(nums)

        # 初始化前两个位置
        dp[0] = nums[0]
        dp[1] = max(nums[0], nums[1])

        for i in range(2, len(nums)):
            # 方案 1：不偷当前房子，沿用前一个答案
            # 方案 2：偷当前房子，那就加上 dp[i-2]
            dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])

        # 最后一个位置就是全局答案
        return dp[-1]
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 更优版

可以压缩成两个变量：

```python
class Solution:
    def rob(self, nums):
        prev2 = 0
        prev1 = 0

        for num in nums:
            cur = max(prev1, prev2 + num)
            prev2 = prev1
            prev1 = cur

        return prev1
```

## 279. 完全平方数

### 题目

原题：[279. 完全平方数](https://leetcode.cn/problems/perfect-squares/)

给你一个整数 n ，返回 和为 n 的完全平方数的最少数量 。

完全平方数 是一个整数，其值等于另一个整数的平方；换句话说，其值等于一个整数自乘的积。例如，1、4、9 和 16 都是完全平方数，而 3 和 11 不是。

示例 1：

输入：n = 12
输出：3
解释：12 = 4 + 4 + 4

示例 2：

输入：n = 13
输出：2
解释：13 = 4 + 9

提示：

- 1 <= n <= 104

### 思路

把题目先翻译成一句话：

`数字 i，最少能拆成几个完全平方数之和？`

比如：

- `12 = 4 + 4 + 4`，最少是 `3` 个
- `13 = 4 + 9`，最少是 `2` 个

想 `dp[i]` 时，不要想整题，想“最后一个数选谁”：

- 最后一个完全平方数可能是 `1`
- 也可能是 `4`
- 也可能是 `9`

如果最后一个选了 `j*j`，那前面还剩 `i - j*j` 要去凑。

动态规划三件事：

- `状态`：`dp[i]` 表示“凑出数字 i 最少要几个完全平方数”
- `转移`：`dp[i] = min(dp[i], dp[i - j*j] + 1)`
- `初始化`：`dp[0] = 0`，因为凑出 0 不需要任何数

### 口诀

`枚举最后一个平方数`

### 图解

```text
要求 dp[12]，就想最后一个数选谁：

最后选 1：
前面还要凑 11
答案候选 = dp[11] + 1

最后选 4：
前面还要凑 8
答案候选 = dp[8] + 1

最后选 9：
前面还要凑 3
答案候选 = dp[3] + 1

取最小值
```

### 背景知识

- 完全平方数：`1, 4, 9, 16, ...`
- `float("inf")` 表示“正无穷”，这里把它当成“一个特别大的初始值”
- 这样后面一旦找到更小方案，就能顺利用 `min()` 更新

### Python

```python
class Solution:
    def numSquares(self, n):
        # 先把每个位置都设成一个很大的值
        # 表示“目前还不知道最优答案”
        dp = [float("inf")] * (n + 1)

        # 凑出 0 不需要任何平方数
        dp[0] = 0

        # 从 1 一路算到 n
        for i in range(1, n + 1):
            j = 1

            # 枚举所有不超过 i 的完全平方数：1, 4, 9 ...
            while j * j <= i:
                # 如果最后一个平方数选 j*j，
                # 那前面的部分就是 i - j*j
                dp[i] = min(dp[i], dp[i - j * j] + 1)
                j += 1

        return dp[n]
```

### 复杂度

- 时间复杂度：`O(n * sqrt(n))`
- 空间复杂度：`O(n)`

## 322. 零钱兑换

### 题目

原题：[322. 零钱兑换](https://leetcode.cn/problems/coin-change/)

给你一个整数数组 coins ，表示不同面额的硬币；以及一个整数 amount ，表示总金额。

计算并返回可以凑成总金额所需的 最少的硬币个数 。如果没有任何一种硬币组合能组成总金额，返回 -1 。

你可以认为每种硬币的数量是无限的。

示例 1：

输入：coins = [1, 2, 5], amount = 11
输出：3
解释：11 = 5 + 5 + 1

示例 2：

输入：coins = [2], amount = 3
输出：-1

示例 3：

输入：coins = [1], amount = 0
输出：0

提示：

- 1 <= coins.length <= 12

- 1 <= coins[i] <= 231 - 1

- 0 <= amount <= 104

### 思路

这题和“完全平方数”是一个套路，只是“平方数”换成了“硬币”。

题目本质是：

`要凑出金额 i，最少需要几枚硬币？`

想 `dp[i]` 时，去想最后一枚硬币是谁：

- 最后一枚可能是 `1`
- 也可能是 `2`
- 也可能是 `5`

如果最后一枚选 `coin`，那前面还要凑 `i - coin`。

动态规划三件事：

- `状态`：`dp[i]` 表示“凑出金额 i 最少需要多少枚硬币”
- `转移`：`dp[i] = min(dp[i], dp[i - coin] + 1)`
- `初始化`：`dp[0] = 0`，因为凑出 0 元不需要硬币

### 口诀

`枚举最后一枚硬币`

### 图解

以 `coins = [1,2,5], amount = 11` 为例：

```text
要求 dp[11]，就想最后一枚硬币选谁：

最后选 1：
前面还要凑 10
候选答案 = dp[10] + 1

最后选 2：
前面还要凑 9
候选答案 = dp[9] + 1

最后选 5：
前面还要凑 6
候选答案 = dp[6] + 1

取最小值
```

### 背景知识

- 这题和“完全平方数”几乎是同一类模板：都是“枚举最后一个东西”
- 如果某个金额怎么都凑不出来，它会一直保持 `inf`
- 最后如果 `dp[amount]` 还是 `inf`，就说明无解，返回 `-1`

### Python

```python
class Solution:
    def coinChange(self, coins, amount):
        # dp[i] 表示：凑出金额 i 最少需要多少枚硬币
        dp = [float("inf")] * (amount + 1)

        # 凑出 0 元不需要硬币
        dp[0] = 0

        for i in range(1, amount + 1):
            for coin in coins:
                # 只有当 coin 不大于当前金额 i 时，才有资格作为“最后一枚硬币”
                if i >= coin:
                    # 选 coin 做最后一枚时，
                    # 前面要先凑出 i - coin
                    dp[i] = min(dp[i], dp[i - coin] + 1)

        # 如果还是无穷大，说明凑不出来
        return dp[amount] if dp[amount] != float("inf") else -1
```

### 复杂度

- 时间复杂度：`O(amount * len(coins))`
- 空间复杂度：`O(amount)`

## 139. 单词拆分

### 题目

原题：[139. 单词拆分](https://leetcode.cn/problems/word-break/)

给你一个字符串 s 和一个字符串列表 wordDict 作为字典。如果可以利用字典中出现的一个或多个单词拼接出 s 则返回 true。

注意：不要求字典中出现的单词全部都使用，并且字典中的单词可以重复使用。

示例 1：

输入: s = "leetcode", wordDict = ["leet", "code"]
输出: true
解释: 返回 true 因为 "leetcode" 可以由 "leet" 和 "code" 拼接成。

示例 2：

输入: s = "applepenapple", wordDict = ["apple", "pen"]
输出: true
解释: 返回 true 因为 "applepenapple" 可以由 "apple" "pen" "apple" 拼接成。
注意，你可以重复使用字典中的单词。

示例 3：

输入: s = "catsandog", wordDict = ["cats", "dog", "sand", "and", "cat"]
输出: false

提示：

- 1 <= s.length <= 300

- 1 <= wordDict.length <= 1000

- 1 <= wordDict[i].length <= 20

- s 和 wordDict[i] 仅由小写英文字母组成

- wordDict 中的所有字符串 互不相同

### 思路

这题可以理解成：

`字符串前 i 个字符，能不能刚好拆成若干个字典单词？`

比如 `leetcode`：

- 如果前 `4` 个字符 `"leet"` 能拆开
- 后面的 `"code"` 也在字典里

那前 `8` 个字符就也能拆开。

关键想法是“最后一刀切在哪里”。

动态规划三件事：

- `状态`：`dp[i]` 表示“前 i 个字符能不能被成功拆分”
- `转移`：枚举最后一刀切在 `j`
- 如果 `dp[j]` 已经是 `True`，并且 `s[j:i]` 在字典里，那么 `dp[i] = True`
- `初始化`：`dp[0] = True`，因为空字符串可以看成“已经成功拆分”

### 口诀

`看最后一刀能不能切开`

### 图解

以 `s = "leetcode"` 为例：

```text
dp[0] = True   # 空字符串可以被拆分

看 dp[4]:
"leet" 在字典里，并且 dp[0] = True
所以 dp[4] = True

看 dp[8]:
"code" 在字典里，并且 dp[4] = True
所以 dp[8] = True
```

### 背景知识

- `s[j:i]` 表示左闭右开，取下标 `j` 到 `i-1`
- `set(wordDict)` 查找更快，因为集合判断“在不在里面”通常是 `O(1)`
- `dp[0] = True` 很重要，它相当于“第一刀允许从开头切”

### Python

```python
class Solution:
    def wordBreak(self, s, wordDict):
        # 把列表变成集合，查找某个单词是否存在会更快
        word_set = set(wordDict)
        n = len(s)

        # dp[i] 表示：前 i 个字符能不能被成功拆分
        dp = [False] * (n + 1)

        # 空字符串可以看成已经拆分成功
        dp[0] = True

        for i in range(1, n + 1):
            # 枚举最后一刀切在 j
            for j in range(i):
                # 如果前 j 个字符已经能拆开，
                # 并且最后这一段 s[j:i] 也在字典里，
                # 那前 i 个字符就能拆开
                if dp[j] and s[j:i] in word_set:
                    dp[i] = True
                    # 已经找到一种可行拆法，就不用继续试了
                    break

        return dp[n]
```

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(n)`

## 300. 最长递增子序列


### 题目

原题：[300. 最长递增子序列](https://leetcode.cn/problems/longest-increasing-subsequence/)

给你一个整数数组 nums ，找到其中最长严格递增子序列的长度。

子序列 是由数组派生而来的序列，删除（或不删除）数组中的元素而不改变其余元素的顺序。例如，[3,6,2,7] 是数组 [0,3,1,6,2,2,7] 的子序列。

示例 1：

输入：nums = [10,9,2,5,3,7,101,18]
输出：4
解释：最长递增子序列是 [2,3,7,101]，因此长度为 4 。

示例 2：

输入：nums = [0,1,0,3,2,3]
输出：4

示例 3：

输入：nums = [7,7,7,7,7,7,7]
输出：1

提示：

- 1 <= nums.length <= 2500

- -104 <= nums[i] <= 104

进阶：

- 你能将算法的时间复杂度降低到 O(n log(n)) 吗?

### 简单版思路

这题先别管更优解，先学最容易理解的版本。

题目问的是“最长递增子序列”，注意：

- `子序列` 不要求连续
- 只要顺序不乱就行

我们先只想一个更小的问题：

`如果规定必须以 nums[i] 结尾，最长递增子序列有多长？`

这就更容易了，因为只要往前找哪些数比它小，就可以接在它们后面。

动态规划三件事：

- `状态`：`dp[i]` 表示“以 nums[i] 结尾的最长递增子序列长度”
- `转移`：如果 `nums[j] < nums[i]`，就可以把 `nums[i]` 接在 `j` 后面，所以尝试 `dp[j] + 1`
- `初始化`：每个数单独都能构成长度为 `1` 的递增子序列，所以一开始全是 `1`

### 口诀

`以当前数结尾，往前找比它小的`

### 图解

以 `nums = [10,9,2,5,3,7,101,18]` 为例：

```text
到 7 时：
前面比 7 小的有 2、5、3

如果接在 2 后面，长度可能是 2
如果接在 5 后面，长度可能是 3
如果接在 3 后面，长度可能是 3

所以以 7 结尾的最长长度是 3
```

### 背景知识

- “子序列”不要求连续
- 只要求相对顺序不变
- 这题一个常见难点是：全局答案不一定出现在最后一个位置，所以最后要取 `max(dp)`

### 简单版 Python

```python
class Solution:
    def lengthOfLIS(self, nums):
        n = len(nums)

        # dp[i] 表示：以 nums[i] 结尾的最长递增子序列长度
        # 每个数自己都能单独组成一个长度为 1 的序列
        dp = [1] * n  # 每个数自己都能构成长度为 1 的递增子序列

        for i in range(n):
            for j in range(i):
                # 只有前面的数比当前数小，当前数才能接在它后面
                if nums[j] < nums[i]:
                    dp[i] = max(dp[i], dp[j] + 1)

        # 答案不一定以最后一个数结尾，所以要取整个 dp 的最大值
        return max(dp)
```

### 简单版复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(n)`

### 更优版

更优版是“贪心 + 二分”，时间复杂度 `O(n log n)`，但记忆成本更高。
如果目标是先背住 Hot100，这题先把上面的 `O(n^2)` 版本背熟最稳。

## 152. 乘积最大子数组

### 题目

原题：[152. 乘积最大子数组](https://leetcode.cn/problems/maximum-product-subarray/)

给你一个整数数组 nums ，请你找出数组中乘积最大的非空连续 子数组（该子数组中至少包含一个数字），并返回该子数组所对应的乘积。

测试用例的答案是一个 32-位 整数。

请注意，一个只包含一个元素的数组的乘积是这个元素的值。

示例 1:

输入: nums = [2,3,-2,4]
输出: 6
解释: 子数组 [2,3] 有最大乘积 6。

示例 2:

输入: nums = [-2,0,-1]
输出: 0
解释: 结果不能为 2, 因为 [-2,-1] 不是子数组。

提示:

- 1 <= nums.length <= 2 * 104

- -10 <= nums[i] <= 10

- nums 的任何子数组的乘积都 保证 是一个 32-位 整数

### 思路

这题最容易卡住的地方是：

`乘积` 和 `加法` 不一样，负数会把大小关系翻过来。

比如：

- 现在一个很小的负数，乘上另一个负数，反而可能变成很大的正数

所以只记“最大值”不够，还要同时记“最小值”。

动态规划三件事：

- `状态 1`：`cur_max` 表示“以当前下标结尾的最大乘积”
- `状态 2`：`cur_min` 表示“以当前下标结尾的最小乘积”
- `转移`：当前数 `num` 来了以后，它可能：
  - 自己单独开一个新子数组
  - 接在前一个最大乘积后面
  - 接在前一个最小乘积后面
- `初始化`：一开始最大、最小、答案都等于第一个数

### 口诀

`乘积题要同时记最大和最小`

### 图解

以 `nums = [2,3,-2,4]` 为例：

```text
到 -2 时：

最大乘积可能来自：
-2 自己
前一个最大 * -2
前一个最小 * -2

因为负负得正
所以“最小”也可能帮你变成“最大”
```

### 背景知识

- 负数会让大小关系翻转
- 所以不能只记一个最大值
- 这题虽然常写成变量滚动更新，但本质也是动态规划

### Python

```python
class Solution:
    def maxProduct(self, nums):
        # 一开始，只有第一个数可选
        cur_max = nums[0]
        cur_min = nums[0]
        ans = nums[0]

        for i in range(1, len(nums)):
            num = nums[i]

            # 当前以 num 结尾的乘积，只可能来自这三种情况：
            # 1. num 自己单独开始
            # 2. 接在前一个最大乘积后面
            # 3. 接在前一个最小乘积后面（负负得正）
            candidates = (num, cur_max * num, cur_min * num)
            cur_max = max(candidates)
            cur_min = min(candidates)

            # 每走一步，都更新全局最大答案
            ans = max(ans, cur_max)

        return ans
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

## 416. 分割等和子集

### 题目

原题：[416. 分割等和子集](https://leetcode.cn/problems/partition-equal-subset-sum/)

给你一个 只包含正整数 的 非空 数组 nums 。请你判断是否可以将这个数组分割成两个子集，使得两个子集的元素和相等。

示例 1：

输入：nums = [1,5,11,5]
输出：true
解释：数组可以分割成 [1, 5, 5] 和 [11] 。

示例 2：

输入：nums = [1,2,3,5]
输出：false
解释：数组不能分割成两个元素和相等的子集。

提示：

- 1 <= nums.length <= 200

- 1 <= nums[i] <= 100

### 思路

如果总和是奇数，肯定不能分成两半。

如果总和是偶数，问题变成：

- 能不能从数组里选一些数，使它们的和等于 `sum(nums) // 2`

这就是一个很标准的 `0-1 背包`。

这里的“背包”不用怕，你先把它理解成：

`每个数只能选 0 次或 1 次，问目标和能不能凑出来。`

动态规划三件事：

- `状态`：`dp[j]` 表示“和 j 能不能被凑出来”
- `转移`：如果原来 `j - num` 能凑出来，那么把 `num` 选上以后，`j` 也能凑出来
- `初始化`：`dp[0] = True`，因为什么都不选就能凑出 0

### 口诀

`先看总和能不能平分，再做 0-1 背包`

### 图解

以 `nums = [1,5,11,5]` 为例：

```text
总和 = 22
目标 = 11

问题变成：
能不能选出一些数，正好凑出 11

比如:
11 自己就能凑出
所以答案是 True
```

### 背景知识

- 0-1 背包里，每个数只能用一次
- 所以 `j` 要从大到小遍历，避免同一个数在一轮里被重复使用
- 如果你从小到大更新，就会把“当前这个数”反复拿很多次，那就变成完全背包了

### Python

```python
class Solution:
    def canPartition(self, nums):
        # 先算总和，只有总和能平分，才有机会分成两半
        total = sum(nums)

        if total % 2 == 1:
            return False

        target = total // 2

        # dp[j] 表示：和 j 能不能被凑出来
        dp = [False] * (target + 1)

        # 不选任何数，就能凑出 0
        dp[0] = True

        for num in nums:
            # 倒着遍历，保证每个数只用一次
            for j in range(target, num - 1, -1):
                # 如果 j-num 能凑出来，那么把 num 选上后，j 也能凑出来
                dp[j] = dp[j] or dp[j - num]

        return dp[target]
```

### 复杂度

- 时间复杂度：`O(n * target)`
- 空间复杂度：`O(target)`

## 32. 最长有效括号

### 题目

原题：[32. 最长有效括号](https://leetcode.cn/problems/longest-valid-parentheses/)

给你一个只包含 '(' 和 ')' 的字符串，找出最长有效（格式正确且连续）括号 子串 的长度。

左右括号匹配，即每个左括号都有对应的右括号将其闭合的字符串是格式正确的，比如 "(()())"。

示例 1：

输入：s = "(()"
输出：2
解释：最长有效括号子串是 "()"

示例 2：

输入：s = ")()())"
输出：4
解释：最长有效括号子串是 "()()"

示例 3：

输入：s = ""
输出：0

提示：

- 0 <= s.length <= 3 * 104

- s[i] 为 '(' 或 ')'

### 思路

这题难点不在代码，而在“`dp[i]` 到底记什么”。

这里不要记“前 i 个字符的答案”，而要记：

`以下标 i 结尾的最长有效括号长度。`

为什么这样定义？

因为只有把“结尾固定住”，我们才知道新来的 `)` 能不能和前面配成一段完整答案。

动态规划三件事：

- `状态`：`dp[i]` 表示“以下标 i 结尾的最长有效括号长度”
- `转移`：只有 `s[i] == ')'` 时才可能更新
- `初始化`：全都先设成 `0`，表示“目前还没有形成有效括号”

更新时分两种情况：

1. `...()`：前一个字符是 `'('`，那就直接新增一对
2. `...))`：前一个字符也是 `')'`，那就看前一段有效括号的前面，能不能再找到一个 `'('` 跟当前这个 `')'` 配上

### 口诀

`只在右括号处更新，想办法往前配对`

### 图解

以 `s = "()(())"` 为例：

```text
下标: 0 1 2 3 4 5
字符: ( ) ( ( ) )

到下标 1:
"()" -> dp[1] = 2

到下标 4:
最后这个 ")" 前面是 "("
所以它们能直接配成 "()"

到下标 5:
前一个位置本来已经有一段有效括号
再往前找，发现还能配上新的 "("
于是整段会被接长
```

### 背景知识

- 这题是这组里较难的一题
- 先记最核心的一句：`dp[i]` 只表示“以 i 结尾”
- 这题最容易错的地方是下标推导，先看懂“match_index 是谁”比硬背代码更重要

### Python

```python
class Solution:
    def longestValidParentheses(self, s):
        n = len(s)

        # dp[i] 表示：以下标 i 结尾的最长有效括号长度
        dp = [0] * n
        ans = 0

        for i in range(1, n):
            if s[i] == ")":
                # 情况 1: 直接形成 "()"
                if s[i - 1] == "(":
                    dp[i] = 2

                    # 如果前面还有一段有效括号，可以接上
                    if i >= 2:
                        dp[i] += dp[i - 2]
                else:
                    # 情况 2: 前一个也是 ")"
                    # 先拿到以前一个位置结尾的有效长度
                    prev_len = dp[i - 1]

                    # 再去找：和当前这个 ")" 配对的 "(" 应该在哪
                    match_index = i - prev_len - 1

                    if match_index >= 0 and s[match_index] == "(":
                        # 先把前一段有效括号 + 新配成的一对括号算进去
                        dp[i] = dp[i - 1] + 2

                        # 如果这对括号左边还有别的有效括号，也可以再接上
                        if match_index - 1 >= 0:
                            dp[i] += dp[match_index - 1]

                # 每次更新后，顺手维护全局最大值
                ans = max(ans, dp[i])

        return ans
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 更优版

还有栈解法，也很经典。  
但如果你现在主打“快速记忆”，先记住这个 DP 版本的核心句子：

`dp[i] 只看以 i 结尾的最长有效括号`
