# Hot100 链表题解

核心：`先看清节点怎么连，再动指针。`

## 先修课：链表基础入门

如果你第一次系统做链表题，先把这一节看完。链表题难的地方通常不是算法本身，而是`指针一改就容易绕晕`。

### 1. 什么是链表？

链表可以理解成：`一个节点牵着下一个节点。`

最常见的单链表节点长这样：

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val      # 当前节点存的值
        self.next = next    # 指向下一个节点
```

如果有一条链表 `1 -> 2 -> 3`，它在内存里的意思是：

```text
head
  |
  v
[1|next] -> [2|next] -> [3|None]
```

这里最关键的一点是：

- 数组靠下标找位置
- 链表靠 `next` 一个一个往后走

所以链表题本质上一直在做两件事：

- 找到某个节点
- 改掉某个节点的 `next`

### 2. 为什么链表题总在画图？

因为链表不像数组那样一眼能看到位置关系。

比如反转一小段链表时，`cur.next = prev` 这一句会真的把箭头改掉。如果你没先想清楚“谁指向谁”，很容易把后面的链表弄丢。

所以做链表题的基本习惯是：

1. 先画出当前节点关系
2. 再决定先保存谁
3. 最后才改 `next`

一句话记忆：

`链表题先画箭头，再写代码。`

### 3. 什么是 dummy 节点？

`dummy` 是一个“额外加在最前面的假头节点”。

它本身通常不算答案的一部分，但它很好用，因为很多题都会改到头节点。如果没有 dummy，头节点经常要单独讨论；有了 dummy，头节点就和普通节点一样处理。

示意图：

```text
dummy -> 1 -> 2 -> 3
```

最后真正返回时，一般返回：

```python
dummy.next
```

它特别适合这几类题：

- 删除头节点
- 在头部插入节点
- 交换一对节点
- 按组翻转链表

一句话记忆：

`dummy 的作用，就是把“头节点很特殊”变成“头节点也普通”。`

### 4. 什么是快慢指针？

快慢指针就是两个人同时在链表上走：

- `slow` 每次走 1 步
- `fast` 每次走 2 步

它常见的用途有两个：

1. 找中点  
因为 `fast` 走到末尾时，`slow` 大概在中间。

2. 判环  
如果链表里有环，快指针早晚会在环里追上慢指针。

示意理解：

```text
slow: 1 -> 2 -> 3 -> 4
fast: 1 -> 3 -> 5 -> ...
```

一句话记忆：

`一个走得快，一个走得慢，就能拿到“中点”和“成环”这两类信息。`

### 5. 反转链表时到底在做什么？

反转链表不是把值倒过来，而是把`箭头方向`反过来。

原来是：

```text
1 -> 2 -> 3 -> None
```

反转后变成：

```text
1 <- 2 <- 3    也就是    3 -> 2 -> 1 -> None
```

最经典的 3 个指针是：

- `prev`：已经反转好的前半段头节点
- `cur`：当前正在处理的节点
- `nxt`：先暂存 `cur` 后面的节点，防止断链

顺序一定是：

1. 先记住后面是谁：`nxt = cur.next`
2. 再改箭头方向：`cur.next = prev`
3. 再一起往前走

一句话记忆：

`先存后路，再改箭头。`

### 6. 链表题最常见的出错点

- 忘了先保存 `next`，结果后面的链断了
- 改完头节点后，没有返回新的头
- 删除节点时，没有找到“待删节点的前一个”
- 以为在改值，其实题目要求改节点连接关系

建议你每做一道链表题都先问自己：

1. 这一题要改哪个节点的 `next`？
2. 改之前要先保存谁？
3. 最后返回的是原来的 `head`，还是新的头节点？

## 160. 相交链表


### 题目

原题：[160. 相交链表](https://leetcode.cn/problems/intersection-of-two-linked-lists/)

给你两个单链表的头节点 headA 和 headB ，请你找出并返回两个单链表相交的起始节点。如果两个链表不存在相交节点，返回 null 。

图示两个链表在节点 c1 开始相交：

题目数据 保证 整个链式结构中不存在环。

注意，函数返回结果后，链表必须 保持其原始结构 。

自定义评测：

评测系统 的输入如下（你设计的程序 不适用 此输入）：

- intersectVal - 相交的起始节点的值。如果不存在相交节点，这一值为 0

- listA - 第一个链表

- listB - 第二个链表

- skipA - 在 listA 中（从头节点开始）跳到交叉节点的节点数

- skipB - 在 listB 中（从头节点开始）跳到交叉节点的节点数

评测系统将根据这些输入创建链式数据结构，并将两个头节点 headA 和 headB 传递给你的程序。如果程序能够正确返回相交节点，那么你的解决方案将被 视作正确答案 。

示例 1：

输入：intersectVal = 8, listA = [4,1,8,4,5], listB = [5,6,1,8,4,5], skipA = 2, skipB = 3
输出：Intersected at '8'
解释：相交节点的值为 8 （注意，如果两个链表相交则不能为 0）。
从各自的表头开始算起，链表 A 为 [4,1,8,4,5]，链表 B 为 [5,6,1,8,4,5]。
在 A 中，相交节点前有 2 个节点；在 B 中，相交节点前有 3 个节点。
— 请注意相交节点的值不为 1，因为在链表 A 和链表 B 之中值为 1 的节点 (A 中第二个节点和 B 中第三个节点) 是不同的节点。换句话说，它们在内存中指向两个不同的位置，而链表 A 和链表 B 中值为 8 的节点 (A 中第三个节点，B 中第四个节点) 在内存中指向相同的位置。

示例 2：

输入：intersectVal = 2, listA = [1,9,1,2,4], listB = [3,2,4], skipA = 3, skipB = 1
输出：Intersected at '2'
解释：相交节点的值为 2 （注意，如果两个链表相交则不能为 0）。
从各自的表头开始算起，链表 A 为 [1,9,1,2,4]，链表 B 为 [3,2,4]。
在 A 中，相交节点前有 3 个节点；在 B 中，相交节点前有 1 个节点。

示例 3：

输入：intersectVal = 0, listA = [2,6,4], listB = [1,5], skipA = 3, skipB = 2
输出：No intersection
解释：从各自的表头开始算起，链表 A 为 [2,6,4]，链表 B 为 [1,5]。
由于这两个链表不相交，所以 intersectVal 必须为 0，而 skipA 和 skipB 可以是任意值。
这两个链表不相交，因此返回 null 。

提示：

- listA 中节点数目为 m

- listB 中节点数目为 n

- 1 <= m, n <= 3 * 104

- 1 <= Node.val <= 105

- 0 <= skipA <= m

- 0 <= skipB <= n

- 如果 listA 和 listB 没有交点，intersectVal 为 0

- 如果 listA 和 listB 有交点，intersectVal == listA[skipA] == listB[skipB]

进阶：你能否设计一个时间复杂度 O(m + n) 、仅用 O(1) 内存的解决方案？

### 思路

双指针分别走 A+B 和 B+A，总路程相同后会在相交点相遇。

### 口诀

`走完自己再走对方`

### 图解

```text
A 走到尾 -> 去 B
B 走到尾 -> 去 A
相遇点就是答案
```

### Python

```python
class Solution:
    def getIntersectionNode(self, headA, headB):
        a, b = headA, headB
        while a != b:
            a = a.next if a else headB
            b = b.next if b else headA
        return a
```

### 复杂度

- 时间复杂度：`O(m+n)`
- 空间复杂度：`O(1)`

## 206. 反转链表


### 题目

原题：[206. 反转链表](https://leetcode.cn/problems/reverse-linked-list/)

给你单链表的头节点 head ，请你反转链表，并返回反转后的链表。

示例 1：

输入：head = [1,2,3,4,5]
输出：[5,4,3,2,1]

示例 2：

输入：head = [1,2]
输出：[2,1]

示例 3：

输入：head = []
输出：[]

提示：

- 链表中节点的数目范围是 [0, 5000]

- -5000 <= Node.val <= 5000

进阶：链表可以选用迭代或递归方式完成反转。你能否用两种方法解决这道题？

### 思路

这题不要一上来就记代码，先想清楚一件事：

链表原来是这样走的：

`1 -> 2 -> 3 -> 4 -> None`

反转后要变成：

`1 <- 2 <- 3 <- 4    也就是    4 -> 3 -> 2 -> 1 -> None`

所以我们每次做的事，其实只有一句话：

`把当前节点的箭头，改成指向前一个节点`

难点在于：如果你直接改 `cur.next`，就可能把后面的链表弄丢。  
所以必须先把“后面是谁”存起来，再改指针。

整个过程可以理解成三个人分工：

- `prev`：已经反转好的那一段的头
- `cur`：当前正在处理的节点
- `nxt`：提前记住 `cur` 后面的节点，防止链断掉

### 口诀

`一边走，一边反指针`

### 图解

```text
开始时：
prev = None
cur  = 1 -> 2 -> 3 -> 4

第 1 轮：
先记住 nxt = 2
把 1.next 改成 prev(None)

None <- 1    2 -> 3 -> 4
prev   cur   nxt

然后一起往前走：
prev = 1
cur = 2

第 2 轮：
1 <- 2    3 -> 4

第 3 轮：
1 <- 2 <- 3    4

第 4 轮：
1 <- 2 <- 3 <- 4

循环结束后：
prev 指向的新头节点就是 4
```

### 背景知识

- 链表节点通常长这样：`值 + next 指针`
- `None` 表示“后面没有节点了”
- 反转链表不是改节点里的值，而是改 `next` 指向
- 这题最容易错的地方是：还没保存后继节点，就先改了 `cur.next`

### Python

```python
class Solution:
    def reverseList(self, head):
        # prev 表示“已经反转好的那一段”的头节点
        prev = None

        # cur 表示“当前正在处理哪个节点”
        cur = head

        while cur:
            # 一定要先把后面的节点记住
            # 不然一旦改了 cur.next，后面的链表就找不到了
            nxt = cur.next

            # 这一步就是反转的核心：
            # 原来 cur 指向后面，现在改成指向前面
            cur.next = prev

            # prev 和 cur 一起往前挪
            # 处理完 cur 后，它就进入“已经反转好”的区域了
            prev = cur
            cur = nxt

        # 循环结束时，prev 正好指向新的头节点
        return prev
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

## 234. 回文链表


### 题目

原题：[234. 回文链表](https://leetcode.cn/problems/palindrome-linked-list/)

给你一个单链表的头节点 head ，请你判断该链表是否为回文链表。如果是，返回 true ；否则，返回 false 。

示例 1：

输入：head = [1,2,2,1]
输出：true

示例 2：

输入：head = [1,2]
输出：false

提示：

- 链表中节点数目在范围[1, 105] 内

- 0 <= Node.val <= 9

进阶：你能否用 O(n) 时间复杂度和 O(1) 空间复杂度解决此题？

### 思路

快慢指针找中点，反转后半段，再两边比。

### 口诀

`找中点，反后半，再比较`

### 图解

```text
前半段 -> middle <- 后半段反转后逐个比
```

### Python

```python
class Solution:
    def isPalindrome(self, head):
        slow = fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
        prev = None
        while slow:
            nxt = slow.next
            slow.next = prev
            prev = slow
            slow = nxt
        left, right = head, prev
        while right:
            if left.val != right.val:
                return False
            left = left.next
            right = right.next
        return True
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

## 141. 环形链表


### 题目

原题：[141. 环形链表](https://leetcode.cn/problems/linked-list-cycle/)

给你一个链表的头节点 head ，判断链表中是否有环。

如果链表中有某个节点，可以通过连续跟踪 next 指针再次到达，则链表中存在环。 为了表示给定链表中的环，评测系统内部使用整数 pos 来表示链表尾连接到链表中的位置（索引从 0 开始）。注意：pos 不作为参数进行传递 。仅仅是为了标识链表的实际情况。

如果链表中存在环 ，则返回 true 。 否则，返回 false 。

示例 1：

输入：head = [3,2,0,-4], pos = 1
输出：true
解释：链表中有一个环，其尾部连接到第二个节点。

示例 2：

输入：head = [1,2], pos = 0
输出：true
解释：链表中有一个环，其尾部连接到第一个节点。

示例 3：

输入：head = [1], pos = -1
输出：false
解释：链表中没有环。

提示：

- 链表中节点的数目范围是 [0, 104]

- -105 <= Node.val <= 105

- pos 为 -1 或者链表中的一个 有效索引 。

进阶：你能用 O(1)（即，常量）内存解决此问题吗？

### 思路

把它想成操场跑圈：

- `slow` 每次走 1 步
- `fast` 每次走 2 步

如果链表没有环，`fast` 最后一定会先走到 `None`。  
如果链表有环，`fast` 会在圈里不断追上 `slow`。

所以这题不用真的去“标记访问过的节点”，只要看两个人会不会相遇。

### 口诀

`一快一慢，能追上就有环`

### 图解

```text
没有环：
1 -> 2 -> 3 -> None
fast 会先走到空

有环：
1 -> 2 -> 3 -> 4
     ^         |
     |_________|

slow: 一次走 1 步
fast: 一次走 2 步

因为 fast 比 slow 快，
只要它们一直在圈里绕，早晚会撞上
```

### 背景知识

- `fast and fast.next` 的意思是：先确保 `fast` 不为空，再确保它后面还有一个节点
- 因为 `fast` 每次要走两步，所以必须先检查两层
- `slow == fast` 比较的是“是不是同一个节点对象”，不是值相等

### Python

```python
class Solution:
    def hasCycle(self, head):
        # 两个指针都从头开始
        slow = fast = head

        # fast 一次走两步，所以要先确认：
        # 1. fast 不是空
        # 2. fast.next 也不是空
        while fast and fast.next:
            # slow 走一步
            slow = slow.next

            # fast 走两步
            fast = fast.next.next

            # 如果它们指向了同一个节点，说明有环
            if slow == fast:
                return True

        # 能走到这里，说明 fast 提前走到链表尽头了，没有环
        return False
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

## 142. 环形链表 II


### 题目

原题：[142. 环形链表 II](https://leetcode.cn/problems/linked-list-cycle-ii/)

给定一个链表的头节点 head ，返回链表开始入环的第一个节点。 如果链表无环，则返回 null。

如果链表中有某个节点，可以通过连续跟踪 next 指针再次到达，则链表中存在环。 为了表示给定链表中的环，评测系统内部使用整数 pos 来表示链表尾连接到链表中的位置（索引从 0 开始）。如果 pos 是 -1，则在该链表中没有环。注意：pos 不作为参数进行传递，仅仅是为了标识链表的实际情况。

不允许修改 链表。

示例 1：

输入：head = [3,2,0,-4], pos = 1
输出：返回索引为 1 的链表节点
解释：链表中有一个环，其尾部连接到第二个节点。

示例 2：

输入：head = [1,2], pos = 0
输出：返回索引为 0 的链表节点
解释：链表中有一个环，其尾部连接到第一个节点。

示例 3：

输入：head = [1], pos = -1
输出：返回 null
解释：链表中没有环。

提示：

- 链表中节点的数目范围在范围 [0, 104] 内

- -105 <= Node.val <= 105

- pos 的值为 -1 或者链表中的一个有效索引

进阶：你是否可以使用 O(1) 空间解决此题？

### 思路

这题分两段记：

1. 先判断有没有环  
   还是用快慢指针，先让它们在环里相遇。

2. 相遇之后怎么找入口  
   让一个指针回到头节点，另一个留在相遇点。  
   然后两个都一次走 1 步，再次相遇的地方就是入环点。

这一步第一次看会觉得像魔法，但你可以先把它当结论记：

`第一次相遇后，一个回头，两个同速再走，再次相遇就是入口`

### 口诀

`第一次相遇后，一个回头走`

### 图解

```text
例子：
1 -> 2 -> 3 -> 4 -> 5
          ^         |
          |_________|

第一次相遇点不一定是 3
可能是在 4，也可能在 5

但只要：
一个指针回到 1
另一个留在第一次相遇点

然后两个都每次走 1 步
它们会在 3 再次相遇
3 就是入环点
```

### 背景知识

- 这题和上一题的前半部分完全一样，先靠快慢指针判断有没有环
- `return None` 表示“没有找到入环节点”
- 题目要返回的是“节点本身”，不是节点值

### Python

```python
class Solution:
    def detectCycle(self, head):
        # 第 1 阶段：先判断有没有环
        slow = fast = head
        while True:
            # fast 走不到两步，说明没有环
            if not fast or not fast.next:
                return None
            slow = slow.next
            fast = fast.next.next
            if slow == fast:
                break

        # 第 2 阶段：一个从头出发，一个从相遇点出发
        # 两个都一次走一步，再次相遇就是入环点
        slow = head
        while slow != fast:
            slow = slow.next
            fast = fast.next
        return slow
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

## 21. 合并两个有序链表


### 题目

原题：[21. 合并两个有序链表](https://leetcode.cn/problems/merge-two-sorted-lists/)

将两个升序链表合并为一个新的 升序 链表并返回。新链表是通过拼接给定的两个链表的所有节点组成的。

示例 1：

输入：l1 = [1,2,4], l2 = [1,3,4]
输出：[1,1,2,3,4,4]

示例 2：

输入：l1 = [], l2 = []
输出：[]

示例 3：

输入：l1 = [], l2 = [0]
输出：[0]

提示：

- 两个链表的节点数目范围是 [0, 50]

- -100 <= Node.val <= 100

- l1 和 l2 均按 非递减顺序 排列

### 思路

这题本质上和“合并两个有序数组”很像：

- `list1` 当前看着一个数
- `list2` 当前看着一个数
- 谁小，就先接谁到答案链表后面

这里最重要的不是比较大小，而是先理解 `dummy`。

`dummy` 叫“虚拟头结点”：

- 它不是题目原来的节点
- 只是我们自己临时造出来的一个假头
- 这样不管答案链表第一个节点是谁，代码都能统一写

否则你会一直纠结：

- 第一个节点还没接的时候怎么写？
- 如果一开始就是空链表怎么办？

### 口诀

`谁小接谁`

### 图解

```text
list1: 1 -> 2 -> 4
list2: 1 -> 3 -> 4

dummy -> ?
cur 指向当前答案链表的最后一个节点

第一轮：
比较 1 和 1
谁先接都可以，这里接 list2 的 1

dummy -> 1

第二轮：
比较 1 和 3
接 list1 的 1

dummy -> 1 -> 1

后面同理

最后把还没走完的那条链表整个接上去就行
```

### 背景知识

- `dummy.next` 才是真正答案链表的头
- `cur` 永远指向“答案链表的最后一个节点”
- `list1 = list1.next` 的意思是：`list1` 这根指针往后挪一格，不是删除节点

### Python

```python
class Solution:
    def mergeTwoLists(self, list1, list2):
        # dummy 是虚拟头结点，方便统一处理“头节点是谁”这个麻烦问题
        dummy = ListNode()

        # cur 永远指向“当前答案链表的最后一个节点”
        cur = dummy

        while list1 and list2:
            # 谁的值更小，就先把谁接到答案链表后面
            if list1.val < list2.val:
                cur.next, list1 = list1, list1.next
            else:
                cur.next, list2 = list2, list2.next

            # 接完后，cur 也要往后走到新尾巴
            cur = cur.next

        # 循环结束后，最多只会剩下一条链表没走完
        # 它本身已经有序，所以整段接上去即可
        cur.next = list1 or list2

        # 真正答案从 dummy.next 开始
        return dummy.next
```

### 复杂度

- 时间复杂度：`O(m+n)`
- 空间复杂度：`O(1)`

## 2. 两数相加


### 题目

原题：[2. 两数相加](https://leetcode.cn/problems/add-two-numbers/)

给你两个 非空 的链表，表示两个非负的整数。它们每位数字都是按照 逆序 的方式存储的，并且每个节点只能存储 一位 数字。

请你将两个数相加，并以相同形式返回一个表示和的链表。

你可以假设除了数字 0 之外，这两个数都不会以 0 开头。

示例 1：

输入：l1 = [2,4,3], l2 = [5,6,4]
输出：[7,0,8]
解释：342 + 465 = 807.

示例 2：

输入：l1 = [0], l2 = [0]
输出：[0]

示例 3：

输入：l1 = [9,9,9,9,9,9,9], l2 = [9,9,9,9]
输出：[8,9,9,9,0,0,0,1]

提示：

- 每个链表中的节点数在范围 [1, 100] 内

- 0 <= Node.val <= 9

- 题目数据保证列表表示的数字不含前导零

### 思路

按位相加，别忘进位。

### 口诀

`按位相加，进位跟着走`

### 图解

```text
每位 = l1 + l2 + carry
```

### Python

```python
class Solution:
    def addTwoNumbers(self, l1, l2):
        dummy = ListNode()
        cur = dummy
        carry = 0
        while l1 or l2 or carry:
            v1 = l1.val if l1 else 0
            v2 = l2.val if l2 else 0
            total = v1 + v2 + carry
            carry = total // 10
            cur.next = ListNode(total % 10)
            cur = cur.next
            l1 = l1.next if l1 else None
            l2 = l2.next if l2 else None
        return dummy.next
```

### 复杂度

- 时间复杂度：`O(max(m,n))`
- 空间复杂度：`O(1)`

## 19. 删除链表的倒数第 N 个结点


### 题目

原题：[19. 删除链表的倒数第 N 个结点](https://leetcode.cn/problems/remove-nth-node-from-end-of-list/)

给你一个链表，删除链表的倒数第 n 个结点，并且返回链表的头结点。

示例 1：

输入：head = [1,2,3,4,5], n = 2
输出：[1,2,3,5]

示例 2：

输入：head = [1], n = 1
输出：[]

示例 3：

输入：head = [1,2], n = 1
输出：[1]

提示：

- 链表中结点的数目为 sz

- 1 <= sz <= 30

- 0 <= Node.val <= 100

- 1 <= n <= sz

进阶：你能尝试使用一趟扫描实现吗？

### 思路

这题的关键不是“删节点”，而是：

`怎么找到倒数第 n 个节点的前一个节点`

因为单链表只能往后走，不能往前退，所以最稳的办法是：

- `fast` 先走 `n` 步
- 然后 `slow` 和 `fast` 一起走

这样当 `fast` 到链表最后一个节点时，
`slow` 就正好停在“待删除节点的前一个节点”。

这里也很适合用 `dummy`，因为：

如果要删的就是头节点，`dummy` 可以帮我们统一处理。

### 口诀

`快先走 n 步`

### 图解

```text
例子：
head = 1 -> 2 -> 3 -> 4 -> 5, n = 2

dummy -> 1 -> 2 -> 3 -> 4 -> 5
slow 和 fast 都先站在 dummy

先让 fast 走 2 步：
slow 在 dummy
fast 在 2

然后一起走：
fast 到 5 时
slow 正好在 3

因为 3 的下一个节点 4
就是倒数第 2 个节点

所以删法是：
3.next = 5
```

### 背景知识

- 单链表删除一个节点，常见写法不是“删这个节点本身”，而是“让前一个节点跳过它”
- 也就是：`pre.next = pre.next.next`
- `dummy = ListNode(0, head)` 表示造一个值为 0 的假头，并让它指向原来的 `head`

### Python

```python
class Solution:
    def removeNthFromEnd(self, head, n):
        # dummy 让“删除头节点”这种特殊情况也能统一处理
        dummy = ListNode(0, head)
        slow = fast = dummy

        # fast 先走 n 步，制造和 slow 的距离差
        for _ in range(n):
            fast = fast.next

        # 当 fast 走到最后一个节点时，
        # slow 会停在“待删除节点的前一个节点”
        while fast.next:
            slow = slow.next
            fast = fast.next

        # 跳过待删除节点
        slow.next = slow.next.next
        return dummy.next
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

## 24. 两两交换链表中的节点


### 题目

原题：[24. 两两交换链表中的节点](https://leetcode.cn/problems/swap-nodes-in-pairs/)

给你一个链表，两两交换其中相邻的节点，并返回交换后链表的头节点。你必须在不修改节点内部的值的情况下完成本题（即，只能进行节点交换）。

示例 1：

输入：head = [1,2,3,4]
输出：[2,1,4,3]

示例 2：

输入：head = []
输出：[]

示例 3：

输入：head = [1]
输出：[1]

提示：

- 链表中节点的数目在范围 [0, 100] 内

- 0 <= Node.val <= 100

### 思路

这题要记住：不是交换值，而是交换节点的位置。

先看一小段：

`pre -> a -> b -> next_group`

我们想把它变成：

`pre -> b -> a -> next_group`

这里 `pre` 表示这一组前面的那个节点。  
用了 `dummy` 之后，就算第一组也一定有“前面那个节点”，代码更好写。

### 口诀

`一组两个，局部交换`

### 图解

```text
pre -> a -> b -> next
变成 pre -> b -> a -> next

动作拆开看：
1. pre.next 指向 b
2. a.next 指向 b 后面的节点
3. b.next 指向 a

这样一组就交换完了
```

### 背景知识

- 这题最容易乱的是：一口气改太多指针
- 所以要先给每个角色起名字：`pre`、`a`、`b`
- 交换完一组后，新的 `pre` 应该走到 `a`
  因为交换后 `a` 在这一组的后面

### Python

```python
class Solution:
    def swapPairs(self, head):
        # dummy 让第一组交换时也有“前驱节点”
        dummy = ListNode(0, head)
        pre = dummy

        # 只有当后面至少还有两个节点时，才能交换
        while pre.next and pre.next.next:
            # a 和 b 是这一组要交换的两个节点
            a = pre.next
            b = a.next

            # 交换这 3 条边：
            # pre -> b
            # a -> b 的后一个
            # b -> a
            pre.next, a.next, b.next = b, b.next, a

            # 交换后，这一组后面的那个节点是 a
            # 下一轮应该从 a 后面继续处理
            pre = a
        return dummy.next
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

## 25. K 个一组翻转链表


### 题目

原题：[25. K 个一组翻转链表](https://leetcode.cn/problems/reverse-nodes-in-k-group/)

给你链表的头节点 head ，每 k 个节点一组进行翻转，请你返回修改后的链表。

k 是一个正整数，它的值小于或等于链表的长度。如果节点总数不是 k 的整数倍，那么请将最后剩余的节点保持原有顺序。

你不能只是单纯的改变节点内部的值，而是需要实际进行节点交换。

示例 1：

输入：head = [1,2,3,4,5], k = 2
输出：[2,1,4,3,5]

示例 2：

输入：head = [1,2,3,4,5], k = 3
输出：[3,2,1,4,5]

提示：

- 链表中的节点数目为 n

- 1 <= k <= n <= 5000

- 0 <= Node.val <= 1000

进阶：你可以设计一个只用 O(1) 额外内存空间的算法解决此问题吗？

### 思路

这题是“反转链表”的升级版，但要分组处理。

可以把每一组想成一个小盒子：

- 先看看接下来够不够 `k` 个节点
- 如果不够，就保持原样，直接结束
- 如果够，就只反转这一小段
- 反转完，再把前后重新接起来

最难的地方不是反转本身，而是：

`怎么只反转 [start, tail] 这一段，并且别把后面弄丢`

所以代码里会先记住：

- `start`：这一组的开头
- `tail`：这一组的结尾
- `nxt`：这一组后面的第一个节点

### 口诀

`够 k 个才翻`

### 图解

```text
例子：
1 -> 2 -> 3 -> 4 -> 5, k = 3

先看前 3 个够不够：
1 -> 2 -> 3   够

先记住：
start = 1
tail = 3
nxt = 4

把 [1,2,3] 反转成：
3 -> 2 -> 1

然后重新接回去：
3 -> 2 -> 1 -> 4 -> 5

下一轮从 4 开始继续看
```

### 背景知识

- `reverse(a, b)` 这种写法通常表示：反转从 `a` 开始，到 `b` 前面结束
- 也就是说区间是左闭右开：`[a, b)`
- 左闭右开的好处是：循环里写 `while cur != b`，边界很清楚

### Python

```python
class Solution:
    def reverseKGroup(self, head, k):
        # 反转区间 [a, b)，也就是从 a 开始，到 b 的前一个结束
        def reverse(a, b):
            prev = None
            cur = a
            while cur != b:
                # 标准反转链表模板
                nxt = cur.next
                cur.next = prev
                prev = cur
                cur = nxt

            # 反转后，这一段的新头节点是 prev
            return prev

        dummy = ListNode(0, head)
        pre = dummy
        while True:
            # tail 用来检查：后面还够不够 k 个节点
            tail = pre
            for _ in range(k):
                tail = tail.next
                if not tail:
                    return dummy.next

            # 记住这一组的后一个节点，反转后还要接回去
            nxt = tail.next

            # start 是这一组反转前的头
            # 反转后它会变成这一组的尾
            start = pre.next

            # pre.next 接上反转后的新头
            pre.next = reverse(start, nxt)

            # 反转前的 start 现在成了尾巴
            # 它后面要接回 nxt
            start.next = nxt

            # 下一轮从这一组的新尾巴后面继续
            pre = start
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

### 思路

哈希表记录“旧节点 -> 新节点”，再补 next 和 random。

### 口诀

`旧新节点一一映射`

### 图解

```text
先复制点，再连边
```

### Python

```python
class Solution:
    def copyRandomList(self, head):
        if not head:
            return None
        mp = {}
        cur = head
        while cur:
            mp[cur] = Node(cur.val)
            cur = cur.next
        cur = head
        while cur:
            mp[cur].next = mp.get(cur.next)
            mp[cur].random = mp.get(cur.random)
            cur = cur.next
        return mp[head]
```

示例 1：

输入：head = [4,2,1,3]
输出：[1,2,3,4]

示例 2：

输入：head = [-1,5,3,4,0]
输出：[-1,0,3,4,5]

示例 3：

输入：head = []
输出：[]

提示：

- 链表中节点的数目在范围 [0, 5 * 104] 内

- -105 <= Node.val <= 105

进阶：你可以在 O(n log n) 时间复杂度和常数级空间复杂度下，对链表进行排序吗？

### 思路

链表排序最稳是归并排序。

### 口诀

`链表排序用归并`

### 图解

```text
分成两半，各自排序，再合并
```

### Python

```python
class Solution:
    def sortList(self, head):
        if not head or not head.next:
            return head
        slow, fast = head, head.next
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
        mid = slow.next
        slow.next = None
        left = self.sortList(head)
        right = self.sortList(mid)
        dummy = ListNode()
        cur = dummy
        while left and right:
            if left.val < right.val:
                cur.next, left = left, left.next
            else:
                cur.next, right = right, right.next
            cur = cur.next
        cur.next = left or right
        return dummy.next
```

- 时间复杂度：`O(n log n)`
- 空间复杂度：递归栈 `O(log n)`

## 23. 合并 K 个升序链表


### 题目

原题：[23. 合并 K 个升序链表](https://leetcode.cn/problems/merge-k-sorted-lists/)

给你一个链表数组，每个链表都已经按升序排列。

请你将所有链表合并到一个升序链表中，返回合并后的链表。

示例 1：

输入：lists = [[1,4,5],[1,3,4],[2,6]]
输出：[1,1,2,3,4,4,5,6]
解释：链表数组如下：
[
1->4->5,
1->3->4,
2->6
]
将它们合并到一个有序链表中得到。
1->1->2->3->4->4->5->6

示例 2：

输入：lists = []
输出：[]

示例 3：

输入：lists = [[]]
输出：[]

提示：

- k == lists.length

- 0 <= k <= 10^4

- 0 <= lists[i].length <= 500

- -10^4 <= lists[i][j] <= 10^4

- lists[i] 按 升序 排列

- lists[i].length 的总和不超过 10^4

### 思路

这题可以先别想“k 条链表”，只想一件事：

`每条链表当前最前面的节点里，谁最小？`

因为每条链表本身已经有序，所以每次真正有资格竞争“最小值”的，
只会是每条链表的头节点。

于是我们把“每条链表当前的头节点”都放进最小堆：

- 堆顶永远是当前最小的节点
- 弹出谁，就把谁接到答案链表后面
- 然后把它的下一个节点再放进堆里

这样就像很多排好序的小队伍，轮流出最小的人。

### 口诀

`最小堆里放每条链表的头`

### 图解

```text
lists = [
  1 -> 4 -> 5
  1 -> 3 -> 4
  2 -> 6
]

开始把每条链表的头放进堆：
1, 1, 2

弹出一个 1，接到答案后面
然后把这个 1 后面的 4 放回堆

堆里又变成：
1, 2, 4

不断重复，直到堆空
```

### 背景知识

- Python 的 `heapq` 是最小堆，最小值会先弹出
- 堆里放 `(node.val, i, node)`：
  `node.val` 用来比大小，`i` 是为了防止值相同的时候直接比较节点对象报错
- `dummy` 还是同样的作用：方便统一拼接答案链表

### Python

```python
import heapq

class Solution:
    def mergeKLists(self, lists):
        heap = []

        # 先把每条链表当前的头节点放进最小堆
        for i, node in enumerate(lists):
            if node:
                heapq.heappush(heap, (node.val, i, node))

        dummy = ListNode()
        cur = dummy

        while heap:
            # 取出当前最小的节点
            _, i, node = heapq.heappop(heap)

            # 接到答案链表后面
            cur.next = node
            cur = cur.next

            # 如果它后面还有节点，就把“这条链表新的头”再放进堆里
            if node.next:
                heapq.heappush(heap, (node.next.val, i, node.next))
        return dummy.next
```

### 复杂度

- 时间复杂度：`O(n log k)`
- 空间复杂度：`O(k)`

## 146. LRU 缓存


### 题目

原题：[146. LRU 缓存](https://leetcode.cn/problems/lru-cache/)

请你设计并实现一个满足 LRU (最近最少使用) 缓存 约束的数据结构。

实现 LRUCache 类：

- LRUCache(int capacity) 以 正整数 作为容量 capacity 初始化 LRU 缓存

- int get(int key) 如果关键字 key 存在于缓存中，则返回关键字的值，否则返回 -1 。

- void put(int key, int value) 如果关键字 key 已经存在，则变更其数据值 value ；如果不存在，则向缓存中插入该组 key-value 。如果插入操作导致关键字数量超过 capacity ，则应该 逐出 最久未使用的关键字。

函数 get 和 put 必须以 O(1) 的平均时间复杂度运行。

示例：

输入
["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"]
[[2], [1, 1], [2, 2], [1], [3, 3], [2], [4, 4], [1], [3], [4]]
输出
[null, null, null, 1, null, -1, null, -1, 3, 4]

解释
LRUCache lRUCache = new LRUCache(2);
lRUCache.put(1, 1); // 缓存是 {1=1}
lRUCache.put(2, 2); // 缓存是 {1=1, 2=2}
lRUCache.get(1);    // 返回 1
lRUCache.put(3, 3); // 该操作会使得关键字 2 作废，缓存是 {1=1, 3=3}
lRUCache.get(2);    // 返回 -1 (未找到)
lRUCache.put(4, 4); // 该操作会使得关键字 1 作废，缓存是 {4=4, 3=3}
lRUCache.get(1);    // 返回 -1 (未找到)
lRUCache.get(3);    // 返回 3
lRUCache.get(4);    // 返回 4

提示：

- 1 <= capacity <= 3000

- 0 <= key <= 10000

- 0 <= value <= 105

- 最多调用 2 * 105 次 get 和 put

### 思路

这题第一次看最容易懵，是因为它把两件事揉在了一起：

1. `get(key)` / `put(key, value)` 要很快找到某个 key  
   这个交给哈希表。

2. 还要知道“谁最近用过，谁最久没用”  
   这个交给双向链表。

你可以把它想成一个书架：

- 哈希表像“目录”，能立刻找到某本书在哪
- 双向链表像“使用顺序队列”
  - 最前面：最近刚用过
  - 最后面：最久没用

每次 `get` 或 `put` 某个 key，都要把它移到最前面。  
如果满了，就删掉最后面那个。

### 口诀

`查找靠哈希，顺序靠双链表`

### 图解

```text
head <-> 最近用过 <-> ... <-> 最久没用 <-> tail

规则：
1. 新访问的，放到 head 后面
2. 淘汰时，删 tail 前面的节点

例子：容量 = 2

put(1, 1)
head <-> 1 <-> tail

put(2, 2)
head <-> 2 <-> 1 <-> tail

get(1)
因为 1 刚被访问，要挪到最前面
head <-> 1 <-> 2 <-> tail

put(3, 3)
容量超了，删最久没用的 2
head <-> 3 <-> 1 <-> tail
```

### 背景知识

- 双向链表节点里会有 `prev` 和 `next`
- 这里的 `head` 和 `tail` 是两个“哨兵节点”，不存真实数据，只是为了方便插入和删除
- 删除一个双向链表节点，只需要改它左右两边的指针
- 哈希表 `mp[key] = node` 表示：这个 key 对应哪个链表节点

### Python

```python
class Node:
    def __init__(self, key=0, val=0):
        # key 要保留下来，因为淘汰节点时要回头删哈希表里的键
        self.key = key
        self.val = val
        self.prev = None
        self.next = None

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity

        # 哈希表：key -> 双向链表中的节点
        self.mp = {}

        # 两个哨兵节点，方便统一处理头插和尾删
        self.head = Node()
        self.tail = Node()
        self.head.next = self.tail
        self.tail.prev = self.head

    def _remove(self, node):
        # 把 node 从双向链表里摘掉
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_to_front(self, node):
        # 把 node 插到 head 后面，表示“最近刚使用过”
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key):
        if key not in self.mp:
            return -1
        node = self.mp[key]

        # 被访问过了，要移动到最前面
        self._remove(node)
        self._add_to_front(node)
        return node.val

    def put(self, key, value):
        if key in self.mp:
            # 已存在：改值，并把它刷新到最前面
            node = self.mp[key]
            node.val = value
            self._remove(node)
            self._add_to_front(node)
            return

        # 不存在：新建节点，放到最前面
        node = Node(key, value)
        self.mp[key] = node
        self._add_to_front(node)

        # 如果超容量，就删掉尾部前面的那个“最久没用节点”
        if len(self.mp) > self.cap:
            old = self.tail.prev
            self._remove(old)
            del self.mp[old.key]
```

### 复杂度

- `get/put` 时间复杂度：`O(1)`
- 空间复杂度：`O(capacity)`
